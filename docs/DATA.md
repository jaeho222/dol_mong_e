# region_metrics.csv 스키마

Agent와 계산 도구가 보는 **유일한 데이터 테이블**. 행 = 비교 단위 지역(14곳), 열 = 지표.
실제 값은 Supabase `refined.region_metrics` view 가 계산하고, `python -m data.build.export_supabase` 가
`data/processed/region_metrics.csv` 로 내보낸다. 계산식 전체: `supabase/sql/20_region_metrics.sql`.
데이터 번호 ↔ 이름 매칭과 받지 않은 데이터의 사유: `docs/DATA_CATALOG.md`.

**권역 판별 방법**: 주소·읍면동 이름은 키워드 표(`refined.region_keyword`)로 14개 권역에 배정한다.
위경도만 있는 데이터는 가장 가까운 버스정류소(612, 4,352곳)의 주소로 권역을 정한다.

## 재미 지수 (backend/tools/region.py `FUN_INDICES`)

추천 순위에는 넣지 않고 결과(`fun_scores`)에 따로 붙인다. 점수는 14개 권역 안에서의 **순위 기반 0~1**
(제일 낮은 곳 0, 제일 높은 곳 1) — 안덕 렌터카 지수(3.96)처럼 한 곳이 튀어도 나머지가 한쪽에 몰리지 않게.
각 계산식은 다른 출처의 데이터와 맞춰 보고 정했다(상관계수 r, 14개 권역).

| 지수 | 계산 | 교차검증 | 버린 대안 |
|---|---|---|---|
| 🚗 렌터카 습격 | `rentcar_index` 순위 | 583 방문 인구 비율(crowd_index)과 r=0.90, 방문/거주 비율과 r=0.89, 거주자당 숙박업소 수(793)와 r=0.56 | 체류 지점 원값: 거주 인구와 r=0.87로 사실상 '인구 많은 동네' 지표가 되고 관광 신호(crowd_index)와는 r=−0.08 |
| ⛰ 오름 부자 | `oreum_cnt` 순위 | 권역 배정을 두 방법(지번주소 / 가장 가까운 정류소)으로 해도 개수가 r=0.82로 일치 | 정류소 기준 배정: 도로에서 먼 중산간 오름이 엉뚱한 권역에 붙는 경우가 있어 주소 기준 채택 |
| 🍜 노포 | `nopo_ratio`(20년 이상) 순위 | 830 신규 개업률과 r=−0.72(오래된 가게 많은 곳 = 새 가게 적음) | 2000년 기준: 순위는 거의 같지만(r=0.94) 개업률과의 관계가 약함(r=−0.57) |
| ☕ 요즘 뜨는 | `new_biz_rate` 순위 | 노포 지수와 반대 방향(r=−0.72)으로 일관됨 | – |

빨래 기준 검증: 일조가 정상인 3개 관측소에서 '습도 65% 미만' 비율과 '습도 70% 미만 + 일조 5시간 이상' 비율이 월별 r=0.91.
877 원본 문제: 제주 관측소 파일의 일조(Sunshine_mean)는 평균 0.38시간/일로 깨져 있고, Solar_mean 은 일사량(MJ/㎡)이라 대신 쓸 수 없다.
그래서 빨래는 습도 기준으로, 1월 일조는 제주만 평년값 70시간으로 둔다.
